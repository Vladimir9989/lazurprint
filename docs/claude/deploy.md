# Деплой на хостинг (deploy.js)

Справочник для ассистента. Читать, когда задача касается `npm run deploy`, `.env`, хостинга NetAngels или сбоев заливки.

## Как устроено

`npm run deploy` = `gulp build` (predeploy) + `node deploy.js` — заливает `build/` на NetAngels.

- Протокол — `DEPLOY_PROTOCOL` в `.env`: `sftp` (по умолчанию) или `ftp`. SFTP + `fastPut` (параллельные чанки) стабильно тянет большие файлы и ~3.5× быстрее обычного `put` (43 МБ: ~105 c против ~374 c). FTP таймаутил на видео >~30 МБ по control-socket — остаётся резервом.
- Креды — `.env` (шаблон `.env.example`, реальный `.env` в `.gitignore`). Два набора: общие `DEPLOY_*` (для ftp) и `DEPLOY_SFTP_*` (для sftp, берутся вместо общих, если заданы). Переключение протокола — одна строка `DEPLOY_PROTOCOL`.
- `dotenv` вызывается с `quiet: true`: без него dotenv v17 печатает рекламные «tips» (`… for agents [vestauth.com]`) — это не prompt injection, просто маркетинг пакета.

## Инкрементальность

- Заливка только upload — на сервере ничего не удаляется (удалённую страницу убирать вручную через файловый менеджер).
- После каждого файла его путь/размер/**sha256** сразу пишутся в `.deploy-manifest.json` (в `.gitignore`). Следующий запуск заливает только новые/изменённые. При обрыве — переподключение и повтор файла (до 4 попыток); повторный `npm run deploy` продолжает с места обрыва. Залить всё с нуля — удалить манифест.
- Сравнение по хешу, не по mtime: gulp при сборке переписывает все файлы `build/`, по mtime каждый деплой заливал бы ~2800 файлов / ~2 ГБ.
- Версия `?_v=` в HTML — из `package.json` + хеш исходников CSS/JS (см. CLAUDE.md, «Версия и кэш браузера»): стабильна между сборками, поэтому HTML не перезаливается без причины.

## Крупные файлы

- Файлы > `DEPLOY_MAX_SIZE_MB` (по умолчанию 50) пропускаются и печатаются списком в начале — заливаются **вручную** через файловый менеджер. Сейчас это три ролика в `images/img/events/` (120–340 МБ), меняются раз в год. Видео ~30–45 МБ идут через SFTP штатно.
- `manualSkip` в `deploy.js` (сейчас пуст) — сюда вписать путь (относительно `build/`, через `/`), если конкретный файл упорно рвёт заливку.
