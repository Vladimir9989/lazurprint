# Индивидуальное оформление новых статей и новостей

Справочник для ассистента. Читать при создании **нового** материала (`articlesNNN.html` / `newsNN.html`). Рядовые правки текста в существующих статьях этого не требуют.

## Правило

Подтверждённое предпочтение пользователя: каждая новая статья или новость получает **собственное уникальное оформление**, а не типовую вёрстку `.news`/`.card`, которой обходятся старые `articles1–110.html` и большинство `newsNN.html`.

## Как устроено

- Стили материала — отдельный partial в **`src/styles/articles/`**, импорт в `styles.scss`: `@import 'articles/имя-файла';`. Один файл на материал.
- **Свой уникальный CSS-префикс классов** — чужой не переиспользовать.
- **Свой цветовой акцент**, отличимый от соседей на `articles.html`/`news.html`. Не брать «ещё один оттенок синего».

## Занятые префиксы и палитры

Материалов уже 30+, поэтому список здесь не ведётся — он живёт в шапках самих файлов. В начале каждого partial есть комментарий: какой материал, префикс, палитра. Актуальная сводка одной командой:

```bash
grep -h -A1 "Префикс\|Палитра" src/styles/articles/*.scss
```

Новый partial начинать с такого же комментария (материал, `.префикс-`, палитра и чем она отличается от соседей) и добавить `@import` в конец списка `articles/` в `styles.scss`. Палитры, которые уже часто встречаются: синий/циан (`.cal-`), сиреневый/бирюзовый, терракота/янтарь, зелёные (`.zont-`, `.znak-`, `.len-`), графит + золото/бронза — их лучше избегать.

Страницы `portfolio.html` (`.pf-` поверх `.cal-*`), `how-to-order.html` (`.ord-`), `raiskiy-sad.html` (`.sad-`), `collection-of-paintings.html` (`.gallery-page`) тоже лежат в этой папке.

## Уровень исполнения (референс, не шаблон)

Hero с фоновыми «блобами» и градиентом, чип-навигация по разделам (`data-spy`/якоря), карточки/сетки с inline-SVG иконками, таймлайны, врезки-цитаты. Состав секций — под контент.

## Чек-лист нового материала

**Начинать с генератора** — он делает всю обвязку (страница с SEO-шапкой и canonical в `<head>`, JSON-LD, SCSS-файл с префиксом + `@import`, карточка в `articles.html`/`news.html`, запись NewsArticle в `news.html`) и сам отказывает, если префикс занят:

```bash
npm run new-page -- article "Заголовок" --prefix xyz --desc "Описание 150–160 символов" [--short "Крошки"] [--date YYYY-MM-DD] [--dry-run]
```

Дальше — `grep TODO` по созданным файлам: текст, палитра и оформление, фото. В конце — `node tools/check-links.js articlesN.html articles.html`.

- Нет фото — не ставить `<img>` на несуществующий файл: CSS-плейсхолдер (пунктирная рамка + подпись, что должно быть на фото) или общий `images/img/articles/file.jpg` для карточки в списке. Сразу предложить промпты для генерации иллюстраций — пользователь генерирует и присылает.
- Промпты с людьми: славянская внешность («young Slavic woman, typical Ural Russian appearance»); принт на одежде — не «close-up portrait», а waist-up/full-body, принт в фокусе и не обрезан.
- Когда появились фото — заменить заглушку `file.jpg` во всех местах: страница, `og:image`, JSON-LD страницы, карточка в списке, для новости — JSON-LD в `news.html`.
- `loading="lazy"` для картинок тела начиная с 3-й.
- `sitemap.xml` обновится сам при сборке.
