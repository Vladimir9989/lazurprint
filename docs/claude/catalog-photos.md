# Фото товаров и добавление продукции в каталог

Справочник для ассистента. Читать, когда пользователь присылает фото новой продукции (`src/images/Новая продукция/`), просит обработать фото товаров или добавить карточки в `catalog-suvenir.html`.

## Требования пользователя (подтверждённые)

- Карточка каталога — **300×300 JPG**, `quality` ~88 (mozjpeg), обычно 15–30 КБ.
- **Фон — идеально белый `#ffffff`.** `whiten-bg.js` — обязательный финальный шаг для любой партии, а не реакция на жалобу. (Общий баланс белого по углам и `flatten-bg.js` давали на сайте сероватые пятна после ресайза и JPEG; только полная заливка белым пользователь назвал «прям идеально».)
- Товар не крупнить: `MARGIN=0.5` (товар ~65% кадра, с воздухом). Тесный кроп не понравился; эталон — `Bloknoty/Puteshestvie po Uralu/_MG_*.jpg`.
- **Открытки** — исключение: не квадрат и не кроп, только убрать серый фон стола (`otkrytki-whiten.js`).

## Инструменты — `tools/img-tools/` (Node + sharp)

Своя `package.json` (`npm install` внутри папки), запускать из этой папки. Не путать с gulp-таском `images`. Константы настройки — в начале файлов (`SAT`, `REL`, `MARGIN`, `TARGET`, `MAXG`, `SIZE`, `QUALITY`): под новую партию обычно поднастраивать их, а не писать с нуля.

| Скрипт | Для чего |
|---|---|
| `resize-catalog.js <src> <out> [--rot90/180/270 файлы]` | Кадр близок к квадрату/портрету: автообрезка по насыщенности (`max-min RGB > 28`, порог `0.12*пик`), квадрат + поле, баланс белого по 4 углам, 300×300. Фильтрует только jpg/png/webp — `.jfif` не возьмёт. |
| `magnity-rezh.js <src> <out> [--preview grid.png]` | Широкий/горизонтальный товар (магниты): плотная обрезка + contain в квадрат на `#f8f8f8`. Понимает jfif. |
| `whiten-bg.js <dir> [--preview grid.png] [--band N]` | Финал: фон → чистый `#ffffff` (**на месте**). Фон = малонасыщенное + связанное с рамкой кадра (BFS) + дилатация + перо. |
| `otkrytki-whiten.js <src> <out> [--sat --lum --core --feather]` | Открытки: белый фон без обрезки/тонирования, размер кадра сохраняется. |
| `flatten-bg.js <dir> [--preview]` | Устаревший для каталога: локально выравнивает фон, но не белит. |
| `montage.js <dir> <out.png> [cols]` | Контактный лист для визуальной проверки (смотреть через Read). |

### Ловушки

- **Калибровочная шкала у края кадра** (`resize-catalog.js`): детектор насыщенности принимает её за товар, bbox растягивается до края — товар мелкий и смещён. Признак в логе: у одного файла `crop NNNpx` заметно больше остальных. Лечение — обрезать край `sharp().extract()` до прогона.
- **EXIF**: sharp по умолчанию поворот не применяет, сырые пиксели телефона обычно уже ровные; крутить только реально лежащие на боку кадры через `--rot270`.
- **`whiten-bg.js` протекает в рисунок**, если бледные зоны товара (небо, белое здание) доходят до края через узкие просветы → флаг `--band N` (для 300×300 обычно `--band 30`) ограничивает глубину заливки от края. Без флага — без ограничения (ок для однородного фона).
- **`otkrytki-whiten.js`**: фон = абсолютный критерий (`max−min ≤ sat` и яркость `≥ lum`), заливка только от края, внутрь «ядра» (bbox открытки × `core`) не пускается. Рабочие параметры партии «Я люблю Реж»: `--sat 30 --lum 108 --core 0.82 --feather 1.2`. При маленьком `core` (~0.5) у светлых открыток виден прямоугольный «шов» — увеличить до ~0.82.
- **sharp и одноканальная маска**: после `.blur()` sharp расширяет маску обратно в 3 канала → полосы при побайтовой индексации. Нужно `.toColourspace('b-w')` перед `.raw()`.

## Процесс добавления продукции

1. Исходники в инбоксе `src/images/Новая продукция/` (вне git и сборки). Посмотреть metadata (формат/размеры/кол-во) и контактный лист — как товар лежит в кадре.
2. Выбрать скрипт по форме товара (см. таблицу).
3. **Обязательно** прогнать с `--preview` и посмотреть глазами до финальной записи. Если фон/свет другой — поднастроить константы.
4. **Прогнать `whiten-bg.js`**, снова проверить превью.
5. Разложить по конвенции: `src/images/img/rs/<Категория>/<kebab-слаг>/<kebab-слаг>-NN.jpg` (пример: `Magnity/ya-lyublyu-rezh/magnit-ya-lyublyu-rezh-01.jpg`).
6. Название, цену, артикул, раздел и место (начало/конец) даёт пользователь — если не дал, спросить, не додумывать.
7. Перед вставкой — **grep по `catalog__subtitle`** в `catalog-suvenir.html`: если раздел с таким названием/размером уже есть, добавлять в него (однажды по ошибке создан дубль «Магнит 50*70»). Разметку `<li class="catalog__item catalog-item">` копировать из соседней карточки 1:1.
8. Правок в `src/` достаточно — dev-сервер пользователя сам пересоберёт `dist/`. Копировать в `dist/` вручную — только если пользователь говорит, что не видит изменений.
9. Коммит/деплой — только после визуального подтверждения и по явной просьбе. Если карточка пришла из админ-панели — после деплоя снять флаги в прод-базе (см. CLAUDE.md, «Админ-панель»).
10. Удалить временные превью, в git не тащить.
