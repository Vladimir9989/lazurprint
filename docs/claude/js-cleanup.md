# ТЗ: порядок в подключении JavaScript по страницам

Рабочее ТЗ для отдельных сессий ассистента. Составлено 2026-10-08 по инвентаризации всех 221 страниц. Пока работа не закончена, файл — живой журнал: в конце раздел «Ход работ», его обновлять после каждой партии. Когда всё будет готово, сократить файл до пары строк итога, а новые правила подключения JS перенести в CLAUDE.md (раздел «Архитектура сборки»).

## 1. Цель и границы

На каждой странице должны подключаться только те скрипты, которые ей реально нужны, в правильном порядке и единым способом. Логика, продублированная по разным файлам, собирается в одно место. Все ошибки JS, найденные по ходу, исправляются.

**В рамках задачи:** теги `<script>` в `src/*.html` и `src/html/*.html`, файлы `src/resources/*.js`, `src/js/**` (бандл `app.js`), инлайн-скрипты страниц, которые открывают форму или дублируют общую логику.

**Вне задачи** (не трогать без отдельной просьбы): вёрстка, стили, тексты, картинки, оптимизация чего-либо кроме JS, админ-панель `admin/`, `mail.php`.

## 2. Обязательные правила работы

1. **Перед началом — коммит.** `git status`: если есть незакоммиченные правки, спросить пользователя, коммитить ли их отдельным коммитом. Работу начинать только с чистого дерева. **После каждой партии — отдельный коммит** (сообщение: «JS: партия N — что сделано»), чтобы можно было откатить любую партию через `git revert`. **Пушить можно, деплоить — нет**: деплой только когда пользователь скажет «деплой» (по правилу CLAUDE.md это сразу коммит, пуш и `npm run deploy`).
2. Не запускать `npm run dev` / `npm run build` (см. CLAUDE.md). У пользователя открыт свой dev-сервер, он сам пересобирает `dist/`. Проверить, что бандл собирается, — `npx gulp scripts`.
3. **Прежде чем убрать скрипт со страницы, доказать, что он там не нужен:** ни один его селектор (`querySelector`, `getElementById`, `new Swiper('…')`) не находит элемент на этой странице — с учётом партиалов `@@include` (header, footer, consultation, reviews, steps…). Ещё проверить, что другие скрипты страницы не используют его глобальные переменные (`Swiper`, `Inputmask`, `JustValidate`, `grecaptcha`, `formModal`…). Сомнение — оставить и записать вопрос в «Ход работ».
4. Порядок `defer`-скриптов = порядок выполнения. Библиотеки идут раньше кода, который их использует.
5. **Браузера у ассистента нет.** ~~После каждой партии — чек-лист и ожидание «ок».~~ **С 2026-10-08 по решению пользователя:** партии 3–9 делать подряд, не останавливаясь на проверку (коммит после каждой — по-прежнему). Всё, что можно, проверять самому (п. 7, `tools/js-smoke.js`). Проверку в браузере пользователь делает **один раз в конце** — по подробной инструкции из п. 7.1, которую ассистент составляет в партии 9. По ходу работ всё, что требует глаз пользователя, записывать в «Ход работ» с пометкой **[в инструкцию]**, чтобы ничего не потерялось.
6. После правок `src/resources/*.js` или `src/js/**` версия `?_v=` в HTML меняется сама (хеш исходников в gulpfile) — бампать ничего не нужно.

## 4. Найденные проблемы (по важности)

**П1. Критично: форма заявки не отправляется на большинстве страниц.** Форма «Рассчитать стоимость» с блоком reCAPTCHA (`.g-recaptcha`) стоит в `html/footer.html`, то есть на каждой странице. Но скрипт Google `recaptcha/api.js` подключён только на 27 страницах из 218. На остальных галочка «Я не робот» не появляется, а `mail.php` без `g-recaptcha-response` заявку отклоняет. Вдобавок `main.js` в `submitHandler` обращается к `grecaptcha` без проверки — там, где скрипта нет, это ReferenceError. Подтверждено на живом сайте: на `how-to-order.html` и `articles123.html` форма открывается кнопками, а скрипта капчи нет. Форму можно открыть минимум на ~47 страницах без капчи (свежие «Как заказать», «Портфолио», «Райский сад», статьи 111–123 и др.) — **чинить в первую очередь**.

**П2. Кнопка «Свяжитесь с нами» в подвале работает только на ~61 странице** — там, где подключён `work.js` (или `catalog-suvenir.js`). На остальных клик ничего не делает.

**П3. Открытие/закрытие формы продублировано в 10+ местах:** `work.js`, `catalog-suvenir.js` (вторая копия того же кода), `how-to-order.js`, `raiskiy-sad.js`, `portfolio.js`, инлайн-скрипты в `articles113, 114, 117, 118, 119, 121, 122` и `socials.html`. Каждый слушает свой класс кнопки (`.hero__btn`, `.consultation__btn`, `.banner-reklama`, `.footer__contacts-btn`, `.catalog__btn`, `.ord-cta`, `.sad-cta`, `.cal-cta`, `.len-cta-open`…). При этом `main.js` в обработчике отправки обращается к глобальной `formModal`, которую объявляет `work.js`. Где `work.js` нет, после успешной отправки — ReferenceError (вероятно, до перехода на `thanks.html` дело не доходит). Проверить.

**П4. Глобальные переменные в общей области видимости.** Старые скрипты (`work.js`, `index.js`, `about.js`, `about-main.js`, `pm.js`, `catalog.js`, `catalog-suvenir.js`, `swiper-JS.js`) объявляют `const`/`let`/`function` на верхнем уровне. У всех обычных `<script>` страницы одна глобальная область. Повторное объявление того же имени через `const`/`let` в другом скрипте даёт SyntaxError, и второй скрипт не выполняется целиком. Примеры имён: `formModal`, `form`, `swiper`, `modal`, `close`, `generateImg` (есть и в `main.js`, и в `index.js`). Бандл `app.js` проходит Babel, `const` там превращается в `var`, а `var` после `const` с тем же именем — тоже SyntaxError. Решение: каждый постраничный скрипт обернуть в IIFE или `DOMContentLoaded`-обработчик, как сделано в новых `how-to-order.js`, `raiskiy-sad.js`, `portfolio.js`.

**П5. Скрипты без проверок падают на «чужих» страницах.** `about.js:5` — `aboutModal.querySelector('video')` без проверки на `null`: на странице без `.video-1` скрипт падает на 5-й строке. `main.js` безусловно вызывает `new Inputmask(...)` и `validateForms('#form')`, поэтому `inputmask` и `just-validate` должны стоять перед `app.js` на каждой странице с подвалом. Пока подвал есть везде, это верно, но об этой зависимости надо помнить. `index.js` безусловно навешивает обработчики на `.benefit-modal` и т.п.

**П6. Swiper в двух вариантах и в разных местах.** CDN v11 синхронно в конце `<body>` (52 стр.) и в `<head>` (4), локальный `swiper-bundle.min.js` (2). Инициализации разбросаны: `swiper-JS.js` (steps, benefit, team), `work.js` (отзывы `.reviews__list`, с проверкой `typeof Swiper`), `index.js`, `events.js`, `catalog.js`, постраничные скрипты статей. Нужна одна версия, подключённая одинаково (`defer` перед скриптами-потребителями), и только там, где на странице есть слайдер.

**П7. Мелочи:** абсолютные пути `/app.js` (20 стр.) рядом с относительными; GA (`gtag`) только на 3 страницах — непонятно, нужен ли он вообще (Метрика стоит везде); `socials.js` синхронно в `<head>` блокирует отрисовку; дубль в `articles13.html`.

## 5. Целевая схема (рекомендация, уточнять по ходу)

1. **Общая логика формы — в бандле `app.js`.** Новый файл `src/js/components/form-modal.js`: открытие по единому атрибуту `data-open-form` на любой кнопке (опционально `data-form-title` / `data-form-desc` / `data-form-text` для подмены заголовка и текста, как сейчас делает `.banner-reklama`), закрытие по крестику и фону, сброс текста. На переходный период поддержать и старые классы (`.hero__btn`, `.consultation__btn`, `.footer__contacts-btn`, `.catalog__btn`, `.ord-cta`, `.sad-cta`, `.cal-cta` и т.д.), а затем перевести разметку на `data-open-form` и удалить дубли из `work.js`, `catalog-suvenir.js`, постраничных скриптов и инлайнов. Учесть: `src/js/components/**` в бандле идёт **перед** `main.js` (concat). Ссылки-кнопки — с `role="button"`, иначе `npm run check` считает их битыми якорями.
2. **reCAPTCHA — лениво.** Не подключать `api.js` статически ни на одной странице: при первом открытии формы динамически добавить `https://www.google.com/recaptcha/api.js?onload=…&render=explicit` и отрисовать виджет в `.g-recaptcha` через `grecaptcha.render`. Так капча будет везде, где есть форма, а страницы без открытой формы не грузят Google. В `main.js` все обращения к `grecaptcha` — через проверку `window.grecaptcha`. Если виджет не загрузился, показать понятное сообщение вместо молчаливой неотправки.
3. **Порядок подключения — единый шаблон в `<head>`, всё своё через `defer`:** библиотеки (`inputmask`, `just-validate`, `swiper` — если нужен) → постраничные скрипты → `app.js`. Внешние счётчики и виджеты — `async`. Синхронных `<script>` в `<body>` не оставлять без причины. Пути — относительные, как у остальных (`app.js`, не `/app.js`).
4. **Постраничные скрипты** — только на своих страницах. Каждый обёрнут в IIFE или `DOMContentLoaded`, каждый `querySelector` с проверкой на `null`.
5. **Swiper** — одна версия: локальный `src/resources/swiper-bundle.min.js` (сверить его версию с CDN v11; если старее — заменить файл на v11 и проверить слайдеры). Подключать с `defer` только на страницах со слайдерами. Аналогично CSS (`swiper-bundle.min.css`).
6. Неподключённые файлы (`cart.js`, `tabs.js`, `vendor.js`, `lazyload.min.js`, `rellax.min.js`) — **удалить только после подтверждения пользователя** (спросить одним списком в конце).

## 7. Проверка после каждой партии

Ассистент:
- `npx gulp scripts` — если менялись `src/js/**` (бандл собирается без ошибок).
- `node tools/check-links.js <страницы партии>` — нет битых путей к скриптам.
- `node tools/js-inventory.js <страницы партии>` — набор и порядок скриптов такие, как задумано.
- `node tools/js-smoke.js <страницы партии>` (или `--all`) — страница из `src/` с партиалами в jsdom, скрипты выполняются как настоящие `<script>` в одной глобальной области (ловит и SyntaxError от повторных `const`), затем кликаются все `[data-open-form]`. jsdom в зависимости проекта не входит — см. шапку скрипта.
- Для каждого убранного скрипта — коротко в «Ход работ», почему он не нужен.

Пользователь — **один раз в конце** (п. 7.1). Инструкция для него — подробная, по шагам: какую страницу открыть, что нажать, что должно произойти, где смотреть ошибки (F12 → Console). Разделить на «это я уже проверил автотестом, можно не смотреть» и «это может проверить только человек» (внешний вид, настоящая капча Google, реальная отправка письма, листание слайдеров пальцем/мышью, видео). Брать пункты из пометок **[в инструкцию]** в «Ход работ».
