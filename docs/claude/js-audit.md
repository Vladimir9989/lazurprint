## Инструкция для проверки (пользователь, один раз)

Подготовка: свой `npm run dev`, сайт (обычно `http://localhost:3000`), на каждой странице **Ctrl+F5** и **F12 → Console**. Красная ошибка в Console = проблема: прислать страницу и текст.

Нет ошибок JS на всех 221 странице; кнопки заявки открывают форму; капча грузится один раз; сообщения формы (нет галочки, капча не загрузилась, «ВЫ РОБОТ», непонятный ответ сервера, обрыв связи), двойное нажатие «Отправить», кнопка не залипает после успеха; неверный email («test@») не уходит; Esc/крестик/фон закрывают; комментарий не стирается при закрытии; Tab не уходит из формы; меню шапки в обоих режимах и при смене режима; бургер; аккордеон подвала; увеличение фото в статьях; видео «О компании»/музей/формы/мероприятия закрываются и останавливаются; счётчики главной доходят до итоговых чисел без наложения; каталог работ — разделы и увеличение; каталог сувениров — сортировки, «По умолчанию», «Назад», поиск, сборка PDF (с подменённой библиотекой); соцсети — фильтры.

### Может проверить только человек

1. **Форма (главное).** Любая страница → «Рассчитать стоимость»: при открытии рамки фокуса на форме нет, вид как раньше. Понажимать **Tab** — фокус ходит по полям, галочке, ссылке и кнопке по кругу, на страницу под окном не уходит; **Esc** закрывает, фокус возвращается на кнопку. Ввести email «test@» → «Отправить» — подсказка «Введите правильный Email». Набрать комментарий, случайно закрыть кликом по фону, открыть снова — комментарий на месте. При отправке надпись «Отправляем…» — тёмная, ошибки — красные.
2. **Обязательно — тестовая отправка на живом сайте после деплоя** (делаете сами): заявка с комментарием «тест, не обрабатывать» → страница «Ваше письмо отправлено», письмо пришло менеджерам. **Если письмо пришло, а форма показала «Не удалось отправить заявку»** — хостинг дописывает в ответ предупреждения PHP: в Console будет строка «неожиданный ответ mail.php» — прислать её. ## Вопросы к пользователю

Серверная часть формы `mail.php` — меняю только с вашего разрешения:

1. **Письмо может не уйти, а посетитель увидит «спасибо».** `mail.php` не проверяет, принял ли почтовый сервер письмо. Предлагаю: при ошибке отправки отвечать «Произошла ошибка» (форма уже покажет «Не удалось отправить заявку…» и в лог хостинга запишется причина). Сделать?
2. **Лимит «5 заявок в час» считает и неудачные попытки** (не та галочка, неверный email). Человек, у которого несколько раз не прошла капча, на 6-й попытке получит «спасибо», а письма не будет. Предлагаю считать в лимит только заявки, прошедшие проверку «Я не робот». Сделать?
3. Что показывать живому человеку, упёршемуся в лимит: оставить «спасибо» (как для бота) или «Слишком много заявок — позвоните нам, пожалуйста»?
4. Ответ `mail.php` в JSON вместо текста — после пунктов 1–2 не обязательно; делать?
5. **Длина имени — до 20 символов**: «Константинопольская Александра» не проходит с подсказкой «Введите ваше имя». Поднять до 50?
6. **Email обязателен.** Оставить обязательным или достаточно телефона?
7. Счётчики цифр на главной считаются заново при каждом появлении блока — так и оставить или один раз?
8. Видео «Коротко о нас»: после закрытия при повторном открытии продолжается с места паузы — так и нужно или начинать сначала?
9. Каталог сувениров: при поиске без результатов — пустое место. Добавить надпись «Ничего не найдено»?
10. **`events.html`, «пароль» к архиву фото — не защита**: пароль и ссылка на Яндекс.Диск (600+ фото) видны в коде страницы любому. Если фото не для всех — поставить пароль на саму папку на Яндекс.Диске или убрать ссылку.
11. Главная: всплывающая форма Битрикс24 показывается не чаще раза в сутки на браузер — это задумка? (не трогал)
12. В рабочей папке лежит пустой файл `src/work.js` (0 байт, не из этой работы, сборкой не используется) — удалить?

## Решение по ES-модулям (2026-10-08)

Рассмотрено и **отложено как невыгодное** для этого сайта: собственный код маленький (на странице 10–20 КБ своего JS, бандл `app.js` — ~10 КБ), основной вес — библиотеки `inputmask` (124 КБ) и `swiper` (155 КБ), их модули не облегчат без перехода на сборщик (esbuild/rollup) вместо текущего gulp-конвейера. Изоляцию кода, ради которой модули обычно и берут, уже дали IIFE. Нативные `import` без сборщика добавят запросы-цепочки и сломают текущую минификацию. Возвращаться, только если сайт перейдёт на сборщик по другим причинам; тогда главный выигрыш — урезанный Swiper (только нужные модули).
