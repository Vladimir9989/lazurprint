# ТЗ: аудит собственного JavaScript сайта

Рабочее ТЗ для следующих сессий ассистента. Составлено 2026-10-08, после чистки подключения JS (`docs/claude/js-cleanup.md` — прочитать раздел «Что сделано», там контекст и инструменты). Пока работа не закончена, файл — живой журнал: раздел «Ход работ» в конце обновлять после каждой партии. Когда всё будет готово — сократить до итога, полезные правила перенести в CLAUDE.md.

## 1. Цель

Прочитать **каждую функцию** собственного JS сайта и ответить на три вопроса: что она делает; работает ли правильно (на всех страницах, где подключена, на телефоне и компьютере, при повторных действиях); можно ли проще/легче/быстрее. Найденные ошибки — исправить, улучшения — сделать, если они не меняют вид и поведение для посетителя (иначе — спросить). **Отдельно и в первую очередь — форма заявки целиком, от кнопки до письма менеджеру.**

## 2. Границы

**В рамках:** `src/js/main.js`, `src/js/components/*.js` (бандл `app.js`), все не-минифицированные `src/resources/*.js` (список в п. 4), инлайн-скрипты страниц (кроме счётчиков в `src/html/counters.html`).

**Только читать и предлагать, менять — с разрешения пользователя:** `src/resources/mail.php` (серверная часть формы), разметка и стили (если исправление JS без них невозможно).

**Вне задачи:** минифицированные библиотеки (`*.min.js`) — их не правим; админ-панель `admin/`; переход на ES-модули/сборщик (рассмотрено и отклонено 2026-10-08, см. п. 8); ленивая загрузка `inputmask`/`just-validate` и облегчение Swiper — уже в бэклоге `WORKLOG.md` («Идеи на будущее»), отдельной задачей.

## 3. Обязательные правила работы

1. Перед началом — `git status`; чужие незакоммиченные правки — спросить, коммитить ли отдельно. Работать с чистого дерева. **После каждой партии — коммит** «JS-аудит: партия N — …». Пушить можно, деплоить — только по слову «деплой» (по CLAUDE.md это коммит + пуш + `npm run deploy`).
2. Не запускать `npm run dev` / `npm run build`. Проверка бандла — `npx gulp scripts`.
3. **Проверка пользователем — одна, в конце** (его правило, см. память «многоэтапные задачи»): партии делать подряд; всё, что требует глаз человека, по ходу помечать в «Ход работ» как **[в инструкцию]**; в последней партии выдать подробную инструкцию «проверено автоматически / только вы».
4. Перед каждой партией и после неё: `npm run js-smoke -- --all --list > before/after.txt` и сравнить — число страниц с ошибками и запущенных слайдеров не должно ухудшиться. Для правок формы — `node tools/js-form-test.js` (после `npx gulp scripts`). jsdom ставится вне проекта: `npm i jsdom@24` в отдельную папку scratchpad, путь — в `JSDOM_DIR`.
5. Для каждой функции, которую меняешь, — сначала найти все страницы, где она работает (`node tools/js-inventory.js`, grep по селекторам с учётом партиалов `src/html/`), и проверить поведение на них.
6. jsdom не умеет: реальную вёрстку и размеры (`offsetHeight` = 0), медиа, `IntersectionObserver` (заглушка), настоящую reCAPTCHA. Всё, что от этого зависит, — в инструкцию для пользователя, а не «проверено».
7. Стиль правок — как в уже приведённых файлах: IIFE или `DOMContentLoaded`, проверки на `null`, комментарии по-русски, без лишних библиотек.
