## 1. Что делаем (кратко)

Человек (или его дети за него) отвечает на 50 вопросов о своей жизни на нашем сайте, прикладывает фото, выбирает переплёт и шрифт и отправляет нам. Мы вычитываем текст, Сергей верстает в готовый шаблон, клиент утверждает макет, мы печатаем 1–N экземпляров.

**Облегчённая версия (сейчас):**
- без аккаунтов и паролей; ответы хранятся **в браузере посетителя** (как корзина сувенирки) — можно закрыть страницу и продолжить завтра **на том же устройстве**;
- кнопка «Скачать копию ответов» (файл Word) — страховка и способ показать родным;
- в конце — одна отправка нам: ответы + фото + выбор оформления + контакты;
- заявка приходит письмом менеджерам и видна в админке `admin/` (раздел «Книги о жизни»).

**Не делаем сейчас** (раздел 9 «Потом»): кабинет с входом, ответ голосом, вопросы от родственников, онлайн-оплата.

## 2. Решения, которые уже приняты

- Три вида переплёта, шаблон макета на каждый (Сергей): 1) скрепка; 2) термоклей; 3) шитьё нитками + твёрдая обложка. Внутри вида — 2–3 объёма с фиксированной ценой.

- Клиент выбирает: переплёт, объём, шрифт (4 варианта), фото на обложку, надпись на обложке.
- Можно пропускать вопросы и добавлять свои (до 10).
- Согласие на обработку персональных данных обязательно (воспоминания и фото — ПДн).

### 3.2 Данные анкеты (`life-book-data.json`)

```json
{
  "version": 1,
  "chapters": [
    { "id": "childhood", "title": "Корни и детство", "questions": [
      { "id": "q01", "text": "…", "hint": "…" }
    ]}
  ],
  "fonts": [ { "id": "pt-serif", "name": "PT Serif", "css": "'PT Serif', serif" } ],
  "bindings": [ { "id": "staple", "name": "Скрепка, мягкая обложка", "sizes": ["до 48 стр.", "до 64 стр."] } ],
  "limits": { "answerMaxChars": 20000, "customQuestionsMax": 10, "photosMax": 40, "photoMaxSidePx": 3500 }
}
```

- У каждого вопроса **постоянный `id`** (`q01`…`q50`). Сохранённые ответы привязаны к `id`, поэтому текст вопроса можно потом править, ответы не потеряются. Новые вопросы получают новые `id`, старые номера не переиспользуются.
- Цен в JSON нет: цены живут только в HTML лендинга (одно место, видно поиску). В анкете при выборе переплёта — ссылка «цены — на странице книги».

### 3.3 Хранение в браузере

- **Ответы, свои вопросы, выбор оформления, контакты** → `localStorage`, ключ `lazurLifeBook` (JSON: `{ v, answers: {q01: "…"}, custom: [{id, text, answer}], design: {...}, contacts: {...}, updatedAt }`). Сохранение — через 500 мс после остановки ввода и при уходе со страницы (`visibilitychange`). Все обращения — в `try/catch`; если хранилище недоступно (приватный режим) — показать предупреждение «ответы не сохранятся при закрытии, скачивайте копию».
- **Фото** → IndexedDB (база `lazurLifeBook`, хранилище `photos`): уже уменьшенные копии + подпись + флаг «на обложку». В localStorage фото не помещаются. Если IndexedDB недоступна — фото живут только до перезагрузки страницы, честно написать об этом.
- Заметная строка в анкете: «Ответы сохраняются только на этом устройстве и в этом браузере».

### 3.4 Фото

- Принимаем JPEG/PNG (`accept="image/jpeg,image/png"`; HEIC с iPhone Safari сам отдаёт как JPEG; на компьютере HEIC — понятная ошибка «сохраните фото как JPEG»).
- В браузере уменьшаем до **3500 px по длинной стороне**, JPEG качество 0.9 (через `createImageBitmap(file, {imageOrientation: 'from-image'})` + canvas, чтобы фото с телефона не легли боком). 3500 px хватает на полосу A4 при ~300 dpi; файл ~2–4 МБ. Фото меньше 1200 px по длинной стороне — принимаем, но с предупреждением «может получиться нечётким в печати».
- До 40 фото, у каждого необязательная подпись (кто, где, год) и отметка «на обложку» (одно).

### 3.5 Отправка на сервер (`life-book.php`)

Отправка идёт по шагам, а не одним запросом: так обходим лимит размера запроса на хостинге и показываем прогресс «загружено 12 из 30 фото».

1. `POST action=start`: контакты, выбор оформления, ответы (JSON), антиспам-поля, токен reCAPTCHA → проверки → создаётся папка заявки, сохраняются `answers.json` и `meta.json` → ответ `{"ok":true,"id":"…","token":"…"}`.
2. `POST action=photo` (по одному фото): `id`, `token`, файл, подпись, флаг обложки → проверка (`getimagesize`, JPEG/PNG, ≤ 15 МБ, не больше `photosMax`) → `photos/01.jpg`… → `{"ok":true}`.
3. `POST action=finish`: `id`, `token` → в `meta.json` ставится «отправлена», собирается `answers.doc`, уходит письмо → `{"ok":true}`.

Ответ — **JSON** (это отдельный обработчик, правило «пустой ответ = успех» из `mail.php` к нему не относится). Ошибка: `{"ok":false,"error":"текст для посетителя"}`.

Сбой посреди загрузки: клиент повторяет фото до 3 раз, затем показывает «Не удалось загрузить фото N — Повторить». Данные в браузере не стираются, пока не пришёл успешный `finish`.

**Хранилище заявок — вне веб-корня:** на хостинге `/home/c112136/lazurprint.ru/life-book/`, путь берётся из `mail-config.php` (новый ключ `life_book_dir`; добавить и в `mail-config.example.php`). Структура:

```
life-book/
  20261102-153012-a7f3c9/
    meta.json      # контакты, оформление, статус загрузки, хэш токена, IP, время, число фото
    answers.json   # ответы как прислали
    answers.doc    # для вычитки и Сергея (HTML с MIME Word, открывается в Word)
    photos/01.jpg 02.jpg …   # + photos.json: подписи и обложка
```

**Безопасность и антиспам** (по образцу `mail.php`):
- honeypot `website` + `form_ts` (для анкеты минимум 60 секунд) + reCAPTCHA v2 на шаге отправки (ключи из `mail-config.php`, скрипт капчи грузить лениво — посмотреть, можно ли переиспользовать загрузчик из `src/js/components/form-modal.js`);
- лимит: не больше 3 **завершённых** заявок в сутки с одного IP;
- имена папок и файлов генерирует сервер; присланное имя файла не используется;
- токен заявки — `bin2hex(random_bytes(16))`, в `meta.json` хранится только хэш, сравнение `hash_equals`; после `finish` токен гасится;
- ответ ≤ `answerMaxChars`, всего JSON ≤ 1 МБ; текст в `answers.doc` и письме — через `htmlspecialchars`;
- **PHP — без синтаксиса PHP 8** (тот же стиль, что `mail.php`, на случай отката версии на хостинге).

**Письмо** (PHPMailer, как в `mail.php`, те же получатели): тема «Книга о жизни: новая заявка — {имя героя}»; в тексте контакты, кто заполнял (сам / за родственника), переплёт, объём, шрифт, надпись на обложке, «ответов X из 50 + своих Y», «фото Z», ссылка в админку; во вложении — `answers.doc`. Фото в письмо не кладём, только в админку.

## 4. Страница-описание `kniga-zhizni.html`

Собственное оформление (как новые статьи, см. `docs/claude/articles-design.md`) в бренде: тёплый тон «семейного альбома» — бумажная фактура/фото, но фирменные синий и галактический. Блоки:

1. **Первый экран:** заголовок «Книга о вашей жизни», подзаголовок «50 вопросов — и история вашей семьи станет настоящей книгой». Кнопка «Начать отвечать» → анкета. Вторая кнопка «Узнать цены» (якорь).
2. **Кому:** подарок родителям, бабушкам и дедушкам, к юбилею; себе — чтобы оставить детям.
3. **Как это работает** (5 шагов): отвечаете на вопросы (в своём темпе, можно пропускать) → добавляете фото → выбираете переплёт и шрифт → мы вычитываем и верстаем, присылаем макет → после вашего «да» печатаем.

5. **Примеры вопросов:** 5–6 штук из списка (по одному из разных глав).
6. **Переплёты и цены** — таблица/карточки по трём видам. Над ней заметная плашка: **«Цены примерные (тестовые) — окончательные уточняются»**. Цены-заглушки:

## 5. Анкета `kniga-zhizni-anketa.html`

Рассчитана на пожилого человека и телефон: крупный шрифт (от 18 px в ответах), большие кнопки, один вопрос на экране, никаких таймеров.

**Экраны:**
1. **Начало:** чья книга (имя героя книги) и кто заполняет («я сам(а)» / «за родственника»). Вопросы выводятся на «вы» в любом случае.

3. **Вопрос:** глава, номер, текст вопроса, подсказка (светлым), большое поле ответа (растёт по мере ввода), отметка «сохранено». Кнопки «Назад», «Пропустить», «Дальше». Счётчик символов — только при приближении к лимиту.
4. **Свои вопросы** (после 50-го или из оглавления): добавить до 10 своих вопросов с ответами.
5. **Фото** (раздел 3.4): выбрать файлы, миниатюры с подписью, «на обложку», удалить.
6. **Оформление:** переплёт и объём (радиокнопки), шрифт — 4 карточки с образцом текста этим шрифтом (абзац из ответа пользователя, если он есть, иначе пример), надпись на обложке (по умолчанию — имя героя).
7. **Отправка:** имя и телефон заказчика (обязательно), email (по желанию), галочка согласия на обработку ПДн со ссылкой на `user-agreement.html`, капча, кнопка «Отправить нам». Перед кнопкой — сводка: ответов, фото, оформление. Если ответов меньше 15 — мягкое предупреждение «книга получится тонкой, можно отправить и так».

**Всегда доступно:** «Скачать копию ответов (Word)» — `.doc` из HTML (Blob с типом `application/msword`), главы, вопросы, ответы; пустые вопросы не включаем.

**Шрифты на выбор** (бесплатные, с кириллицей, у Сергея ставятся без лицензий): PT Serif, Literata, Lora — книжные с засечками; PT Sans — без засечек для тех, кому так легче читать. Подключаются только на анкете.

## 6. 50 вопросов (Владимир правит перед этапом 1)

**Актуальный список — в `src/resources/life-book-data.json`.** 2026-11-02 по совету Татьяны Александровны (слишком объёмные вопросы) упрощены q02, q08, q09, q10, q26, q33, q45, q47, q48: стали конкретнее («одна история», «одна деталь»), глубина остаётся за подсказками. Остальные — без изменений. Ниже — исходная редакция.

Принципы: конкретные и «чувственные», а не общие; трудные темы ближе к концу; формулировки без рода («вы были…» → обходим), чтобы подходили и мужчине, и женщине. Подсказка — что можно рассказать, если не знаете, с чего начать.

**Глава 1. Корни и детство**

## 8. Работа после получения заявки (процесс, не код)

1. Менеджер видит заявку (письмо + админка), звонит клиенту, подтверждает переплёт и тираж, статус «в работе».
2. Вычитка `answers.doc` (Кодер + Владимир): орфография и пунктуация, голос автора не меняем; вопросы-заголовки оставляем или превращаем в названия глав — решить на первом заказе.
3. Сергей верстает в шаблон выбранного переплёта, подгоняет объём под кратность тетрадей, обложка с фото и надписью.
4. Макет (PDF) — клиенту на утверждение. Правки → утверждение → печать → выдача.
5. Через 90 дней после «напечатана» или «отказ» — удалить папку заявки (сначала руками, потом можно cron).

## 10. Лимиты хостинга (проверено 2026-11-02, этап 0)

Замер через веб (PHP 8.2.21, cgi-fcgi), не через консоль — у консоли свои значения:
- `upload_max_filesize`: 128M, `post_max_size`: 128M — фото по 2–4 МБ проходят с запасом;
- `max_file_uploads`: 20 — не мешает, фото грузим по одному;
- `max_execution_time`: 30 с — хватает на одно фото, поэтому отправка идёт по шагам;
- `memory_limit`: 256M — хватает для `getimagesize` и проверок (картинки на сервере не перекодируем);
- `ZipArchive` и `gd` на сервере есть (проверено в консоли);
- место: 658 ГБ свободно из 857 ГБ.
- Вывод: `photoMaxSidePx` остаётся 3500, ограничения не нужны.

## 11. Согласие на обработку ПДн (проверено 2026-11-02, этап 0)

`src/user-agreement.html` — общее соглашение для заказов полиграфии: ФИО, почта, телефон, адреса доставки. Про личные истории, фото родственников и сведения о третьих лицах (родители, дети, ушедшие близкие) там ничего нет, срока хранения и удаления нет. Для этой услуги нужна **отдельная галочка** в анкете с короткой формулировкой (черновик — владельцу на согласование, на сайт без его «да» не выкладывать):

> Я согласен(на) на обработку моих персональных данных, а также текстов и фотографий, которые я присылаю, включая сведения о моих родных, для подготовки и печати книги. Материалы видят только сотрудники типографии, участвующие в подготовке книги. После выдачи заказа типография хранит их 90 дней, затем удаляет. Я подтверждаю, что имею право передавать эти фото и сведения о других людях. Подробнее — в Пользовательском соглашении.

Основное соглашение не трогаем. Срок хранения 90 дней совпадает с разделом 8 (процесс).
