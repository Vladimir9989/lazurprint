# Дорожная карта изменений сайта (продажи)

Часть инициативы [`growth.md`](../../growth.md). Здесь — пошаговый порядок доработок сайта, согласованных с Татьяной Александровной (2026-10-02). Письмам и поиску клиентов посвящён [`outreach-plan.md`](outreach-plan.md).

## Как работаем (правила для каждой фичи)

Делаем **по одной фиче за раз**, не пачкой:

1. Ассистент и пользователь договариваются, какая фича следующая (порядок ниже, можно менять).
2. Ассистент кратко формулирует, что именно будет сделано, какие файлы затронет, и ждёт «ок» (если фича не мелкая).
3. Реализация в `src/` (правила `CLAUDE.md`: не запускать `npm run dev/build`, не править `dist/`/`build/`; новый SCSS → `@import` в `styles.scss`; индивидуальный дизайн — по правилам раздела «Индивидуальное оформление статей и новостей», если это новая страница-материал).
4. Пользователь проверяет у себя на dev-сервере (ассистент даёт короткий чек-лист: что открыть, что нажать, на каких ширинах смотреть).
5. Правки по замечаниям.
6. **Отчёт по фиче:** запись в `DAILY-LOG.md` простым языком (для пересылки Татьяне) + отметка «сделано» ниже в этом файле (дата, коротко что вошло).
7. Коммит, пуш и `npm run deploy` — **только по явной просьбе** пользователя и после его визуального подтверждения. После деплоя вспомнить про `version` в `package.json` (если менялись css/js — бамп вручную).
8. Только потом — следующая фича.

**Где:** страница преимуществ `benefit.html` и блок преимуществ на главной (`src/index.html`, секция `benefit`), форма заявки/консультации (партиал `src/html/consultation.html`), портфолио (`portfolio.html`), позже — «Как заказать» (п. 2) и «Стать партнёром» (п. 5).

### 2. «Как заказать» — ⬜
**Суть:** простой раздел шагами от заявки до доставки: заявка/расчёт → макет (или помощь с ним) → согласование → печать → доставка; закреплённый менеджер ведёт заказ. У Oasis это хорошо понятно новичку; у нас частично есть блок «Последовательность сделки» (`steps` на главной), `require.html` (требования к макетам), `delivery.html`.
**Решить до начала:** отдельная страница `how-to-order.html` (рекомендуется, с индивидуальным оформлением и префиксом) или усиление существующих блоков. Пункт в меню «Клиенту».
**Готово, когда:** страница/блок есть, ссылки на `require.html`, `delivery.html`, форму расчёта, упоминание персонального менеджера.

### 3. Подписка на новости и акции — ⬜
**Суть:** форма «Подписаться» (email) — собирать почту заинтересованных людей для будущих рассылок.
**Решить до начала:** куда уходят адреса (проще всего — письмо на info@ через существующий `mail.php` либо выгрузка в Битрикс; уточнить, есть ли у Битрикса форма подписки/CRM-форма). Согласие на обработку данных — ссылка на `user-agreement.html`/политику, как в других формах. Защита от спама (см. п. 8).
**Где разместить:** подвал (`src/html/footer.html`, на всех страницах) и/или блок в конце статей/новостей.
**Готово, когда:** адрес реально приходит, есть согласие, спам-защита, сообщение «спасибо» без перезагрузки.

**Решить до начала:** формат — отдельная страница с блоками подборок или секция на главной; какие 3–5 подборок делаем первыми (согласовать с пользователем; есть уже статья про выставки `articles113.html`).

### 5. Страница «Стать партнёром» — ⬜ (ждёт решения Татьяны по партнёрским условиям)
**Суть:** три шага (заявка → звонок менеджера → статус партнёра), для кого (агентства, студии, интернет-магазины), что получает партнёр (закреплённый менеджер, образцы, приоритет, расчёт, возможно ступенчатая скидка/вознаграждение — как решит Татьяна), форма заявки. Идея с сайта Oasis (их дилерская программа).
**Не начинать, пока Татьяна не определилась с условиями.** Можно заготовить макет без цифр.

### 6. Форма «Запросить расчёт» — ⬜
**Суть:** структурированная заявка (что печатаем, тираж, формат, срок, прикрепить файл, реквизиты) → на info@ и в Битрикс. Запасной вариант для сложных заказов (книги и т. п.), которые не посчитает калькулятор.
**Решить до начала:** как заявка попадает в Битрикс (`mail.php` → почта → Битрикс сам создаёт лид? или CRM-форма). Спросить пользователя/Яну.

### 7. Онлайн-калькулятор простых заказов — ⬜ (ждёт консультации со Светой Минеевой)
**Суть:** ориентировочная цена **диапазоном «от–до»** для простых продуктов (визитки, листовки, открытки, календари, значки, магниты); сложное (книги, журналы) — «свяжитесь с менеджером». Точный расчёт в программе Assistant повторить невозможно, и этого не требуется.
**Перед началом обязательно:** пользователь консультируется со **Светой Минеевой** (главный технолог ПТО, считает заказы) — см. напоминание в `growth.md`. Нужно получить: список продуктов, которые можно считать формулой; параметры (формат, бумага, тираж, краски, постпечать); сами цены/формулы; допустимую погрешность; её согласие. **Без согласия ПТО не делать.**
