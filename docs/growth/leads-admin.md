## Идея

Новый раздел в существующей админке `admin/` (та же авторизация, PHP 7.3, MySQL, см. `admin/README.md`). Роль «менеджер» видит только его, учёт сувениров не видит. Владимир (админ) наполняет базу клиентов и каталог образцов, менеджеры берут клиентов в работу и пишут письма со своей почты вручную.

## Части

### 1. Клиенты

Поля: компания, сайт, сегмент (издательство / агентство / производитель / периодика…), e-mail «кому», e-mail «копия», обращение («Здравствуйте, Сергей!»), тема, текст письма (с метками `{имя}`, `{должность}`, `{телефон}`), подсказка «какие образцы приложить», «крючок» (повод), источник, «закреплён за менеджером» (необязательно), заметка.

- **Добавление:** пачкой из файла (CSV/JSON) или командой в `admin/tools/` (как `link-site-image.php`): Тестер ищет компании, Кодер пишет письма, десять записей вносятся разом. Ручная форма для единичных.
- **Список новых:** видят все менеджеры, у каждой записи метка «новый». Закреплённых за менеджером (как TATLIN за Надеждой) в общем списке видит только он.
- **«Беру в работу»:** запись переходит в «Мои в работе» этого менеджера и исчезает у остальных. Делать **одним атомарным запросом** («взять, если ещё свободна»), иначе двое нажмут одновременно. Кнопка «Отпустить» возвращает запись в общий список.
- **Подстановка подписи:** при взятии метки `{имя}`, `{должность}`, `{телефон}` заменяются данными менеджера из профиля.
- **Копирование одной кнопкой:** рядом с каждым полем («Кому», «Копия», «Тема», «Текст») кнопка «Скопировать». Дополнительно кнопка «Открыть письмо»: ссылка `mailto:` или составление письма в веб-почте (у Яндекс.Почты и Mail.ru есть адреса вида `compose?to=&subject=&body=`) с подставленными адресом, темой, текстом. Вложения так не добавляются. Зависит от почты менеджеров (см. вопросы).
- **«Я отправил(а)»:** ставит статус «отправлено» и дату.
- **Дубли:** при добавлении проверка по домену сайта и e-mail; показывать «Этой компании писала Ольга 12.09, статус: молчит». Записи не удаляются, уходят в архив. Кнопка «Просили не писать» навсегда блокирует домен (стоп-лист: реклама по e-mail регулируется законом).

### 2. Статусы (зачем)

Статус: новый → взят → отправлен → ответил / отказ / молчит → образец отправлен → заказ. Нужны:

1. **Менеджеру:** свой список «ждём ответа», «кому напомнить через 7–10 дней».
2. **Владимиру:** видно, что происходит, какие письма и сегменты работают, что менять в письмах и образцах.
3. **Татьяне Александровне:** итог пилота цифрами (сколько писем, ответов, образцов, заказов; по менеджерам и сегментам) через 3–4 недели.
4. **Защите от дублей:** клиент со статусом «отправлено» или «отказ» не вернётся в общий список.

Риск: менеджеры должны не забывать ставить статусы (по ответам клиентов). Делать минимум нажатий: одна кнопка на каждый статус.

### 3. Каталог образцов

Категории (книги, журналы, брошюры, коробки, листовки и буклеты, каталоги, газеты, плакаты…), в каждой фото. Загружается **одно фото** (оригинал для письма); сервер (GD) сам делает превью ~300 px для списка (быстрая загрузка страницы). Оригинал для письма ~1600 px, 500–800 КБ (большое растянет письмо и повысит риск спама). Менеджер отмечает несколько фото и скачивает **архивом ZIP** (`ZipArchive` на PHP 7.3) или по одному. Фото не открываются по прямой ссылке без входа (отдавать через PHP с проверкой сессии или из закрытой папки). Подсказки по сегментам: у сегмента «издательство» предвыбраны категории «книги», «журналы» (рекомендация в самом клиенте). Вид: список по категориям или слайдер, без разницы.

### 4. Уведомления

При регистрации менеджер указывает **рабочую почту**. Кнопка у Владимира «Уведомить»: всем менеджерам уходит письмо «Владимир добавил N новых клиентов, посмотрите в админке» (отправка через PHPMailer с ящика noreply, как форма заявки). Это внутренние уведомления, не письма клиентам.

### 5. Пол менеджера (доработка в конце)

Тексты писем пока в женском роде («смотрела», «отправлю»), потому что все менеджеры сейчас женщины. На будущее: поле «пол» в регистрации и подстановка форм по роду (решение Владимира), либо нейтральные формулировки. Делать в самом конце, когда всё остальное работает.

## Что не делаем

- Автоотправку писем с сайта (письма идут с личной почты менеджера: ответы приходят ему, меньше спама).
- Автоматическое прикрепление фото (скачал из каталога → прикрепил сам).

## Этапы

1. Минимум: клиенты, «взять / отпустить», подстановка подписи, кнопки «скопировать», «я отправил», статусы, архив и дубли, загрузка пачкой, уведомление.
2. Каталог образцов: загрузка, превью, категории, ZIP, подсказки по сегментам.
3. Отчёт по менеджерам и сегментам для Татьяны, напоминания молчащим через 7–10 дней, связка с Битрикс24, пол менеджера.

## Про выкладку (для памяти)

Админка на хостинге работает со **своей, отдельной базой MySQL** (там работают Ксюша и Надя; локальная `lazur_admin` тестовая). Новые таблицы нужно создавать **дважды**: сначала локально для проверки, затем отдельным SQL-скриптом на хостинге; `npm run deploy` базу не трогает, данные между базами не переезжают сами. Скрипт для хостинга выполняется через `node admin-remote-exec.js …` (см. `CLAUDE.md`, раздел «Админ-панель»).

## Решения Владимира (2026-10-12)

- **Почта менеджеров:** какая-то корпоративная, возможно Mail.ru; точно не знает, уточнит. До уточнения автозаполнение письма делаем через `mailto:` и кнопки «Скопировать».
- **Видимость:** менеджер видит только общий список свободных клиентов и своих клиентов. Кто что взял из остальных ему не показываем.
- **Молчащие:** если после статуса «отправлено» через **10 дней** менеджер статус не менял (ни «ответили», ни «отказ»), система сама ставит «без ответа». Менеджер может потом поменять вручную. Отдельных напоминаний пока не делаем (можно добавить позже).

- **Реестр для Тестера остаётся** (`outreach-sent.md`), я обновляю его после каждой партии или выгрузкой из базы.
- **Первая десятка (отправлена 2026-10-11/12) переносится в базу сразу с исполнителями:** №3 TATLIN и №10 AMG — Надежда Манькова, остальные восемь — Ольга Чудова, статус «отправлено». Способ: при загрузке пачкой у записи есть поле «ведёт» (ФИО); когда менеджер регистрируется и админ его подтверждает, записи с его ФИО привязываются к нему автоматически. Плюс всегда нужна ручная возможность админа назначить или переназначить менеджера у любой записи (нужна и для случая вроде TATLIN).

- **Клиенты без публичной почты (сети, аптеки, «Фабрика подарков»):** у записи поле «канал» — e-mail или форма на сайте / звонок. Для таких в карточке вместо кнопок «Скопировать адрес» показывается **пошаговая инструкция для менеджера** (зайти на такой-то сайт, открыть такую-то страницу, заполнить такие-то поля, вставить готовый текст). Инструкции готовит Тестер (задание 006, раздел «Сети и аптеки»), текст пишет Кодер. Все письма и заявки отправляют сами менеджеры.
- **Картон:** у типографии только картонная упаковка (гибкую не делаем; уточнить у Татьяны Александровны).
