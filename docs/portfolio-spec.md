# ТЗ: страница «Портфолио» (portfolio.html)

Задание для отдельной сессии Claude Code. Читай вместе с `CLAUDE.md` в корне репозитория — его правила обязательны (особенно: не запускать `npm run dev/build`, не править `dist/`/`build/`, правки только в `src/`).

## 1. Зачем это нужно (контекст)

Новая страница на основном сайте lazurprint.ru с нашими реальными работами. Цели:

1. Показать посетителю живые примеры продукции, повысить доверие.
2. SEO: под каждой работой подпись «Кому подойдёт» — это поисковые фразы вида «печать меню для ресторана», «буклеты для АЗС», «издать книгу» (мы хотим находиться по этим запросам).
3. Страница будет ссылкой в точечных письмах компаниям («вот наше портфолио»), поэтому она должна выглядеть аккуратно и убедительно.

Сейчас фото на сайте не лучшего качества. Заказчик (разработчик сайта) позже улучшит их нейросетью и добавит новые, поэтому **структура должна позволять легко заменять картинки и добавлять карточки** (см. п. 5).

## 2. Что нужно сделать (чек-лист)

1. Создать страницу `src/portfolio.html` с индивидуальным оформлением.
2. Добавить пункт «Портфолио» в выпадающее меню «О компании» в шапке (`src/html/header.html`).
3. Добавить ссылку «Портфолио» в подвал (`src/html/footer.html`, блок «О компании»).
4. На главной (`src/index.html`) заменить кнопку героя «Наши услуги» на «Портфолио» со ссылкой на `portfolio.html`.
5. Создать SCSS-partial `src/styles/articles/_portfolio-page.scss` и подключить в `src/styles/styles.scss` (`@import 'articles/portfolio-page';`, рядом с другими `articles/…`).
6. Скопировать подобранные фото в `src/images/img/portfolio/` (см. п. 5).
7. Дописать запись в `DAILY-LOG.md` (см. п. 9).

## 3. Шапка, подвал, главная

**Шапка** — `src/html/header.html`. Меню «О компании» (`#company-menu`): элементы идут как `<li class="header__elem" role="none" itemprop="name"><a href="…" class="header__elem-link" role="menuitem" title="…" itemprop="url">…</a></li>`. Добавить такой же пункт «Портфолио» (`href="portfolio.html"`, `title="Портфолио типографии Лазурь"`) сразу после «Общая информация». Шапка подключается через `@@include` на всех страницах, поэтому достаточно поправить партиал. Проверить, не дублируется ли меню отдельно для мобильной версии (бургер, `src/styles/_burger.scss`, `src/js/components`/`main.js`): если дублируется — добавить пункт и там.

**Подвал** — `src/html/footer.html`, первый блок `footer__list` («О компании»): добавить `<li class="footer__item"><a href="portfolio.html" class="footer__item-link">Портфолио</a></li>` после «Общая информация».

**Главная** — `src/index.html`, около строки 168:
`<a href="#services" class="hero__btn-secondary">Наши услуги</a>` → `<a href="portfolio.html" class="hero__btn-secondary">Портфолио</a>`.
Секцию `id="services"` («Что мы предлагаем?») не трогать — она остаётся на странице. Остальные кнопки героя («Рассчитать заказ», «Каталог сувениров», «Наша презентация») не менять. Проверить, нет ли других мест, которые ссылаются на якорь `#services` с главной (поиск по `href="#services"`).

## 4. Дизайн страницы

Обязательные правила из `CLAUDE.md` (индивидуальное оформление — `docs/claude/articles-design.md`):

- Собственный SCSS-partial в `src/styles/articles/`, **свой уникальный CSS-префикс** — `.pf-` (не использовать чужие: `.cal-`, `.news-feature`, `.expo-` и др.).
- Современное, аккуратное, светлое оформление в стиле уже сделанных страниц. Образцы для ориентира (не копировать 1:1): `src/styles/articles/_exhibition-article.scss` (`articles113.html`), `_calendars-article.scss`, `_news-feature.scss`, `_beer-mugs-feature.scss` (`news62`). Брендовые цвета и брейкпоинты — `src/styles/_variables.scss`: основной `#3E77FB`, акцент `#6de2eb`, заголовки `#081f5c`. Страница относится к основному сайту, поэтому уместна фирменная сине-голубая гамма с одним тёплым акцентом для чипов/тегов; **не** брать терракотовый (`.expo-`) и сиреневый (`.news-feature`).
- Адаптивность: проверить ширины 320 / 768 / 1024+ — без горизонтального скролла.
- Шапка и подвал — через `@@include('html/header.html', {})` и `@@include('html/footer.html', {})`, как на других страницах.

Состав страницы сверху вниз:

1. **Hero**: заголовок H1 (например «Портфолио типографии «Лазурь»»), подзаголовок в 1–2 строки («Книги, журналы, упаковка, этикетки, каталоги и рекламная продукция — вот что мы печатаем»), фон с мягкими «блобами»/градиентом как в референсах. Хлебные крошки/навигация — как на других страницах.
2. **Чипы-фильтры по категориям** («Все», «Книги», «Журналы», «Каталоги и буклеты», «Упаковка», «Этикетки», «Календари», «Раскраски и учебники», «Реклама и листовки» и т. п. — только те категории, под которые реально нашлись фото). Фильтрация на чистом JS без перезагрузки (простое скрытие/показ карточек по `data-category`). Скрипт — в `src/resources/portfolio.js`, подключается тегом `<script>` на странице (как `index.js`, `catalog.js`; см. раздел «Архитектура сборки» в `CLAUDE.md`). Без фильтра страница тоже должна нормально читаться (прогрессивное улучшение).
3. **Сетка карточек работ**. Карточка: фото (одинаковое соотношение сторон, `object-fit: cover`, `loading="lazy"`), название работы, 1–2 строки описания, блок **«Подойдёт для:»** с тегами-чипами (например «АЗС», «Кафе и рестораны», «Издательства», «Застройщики»), ссылка «Подробнее об услуге» на соответствующую страницу услуги (`books.html`, `packagings.html`, `journal.html`, `catalogs.html`, `label.html`, `calendars.html` и т. д. — проверить, что файлы существуют в `src/`).
4. **Просмотр фото крупно** (lightbox/модалка) по клику на карточку: простое решение на JS/CSS в духе существующих модалок (`src/styles/_modal.scss`) или Swiper (он уже подключается с CDN на других страницах). Не тащить новые тяжёлые библиотеки.
5. **Блок «Не нашли свой вариант?»**: призыв «Расскажите о задаче — рассчитаем и предложим решение» с кнопкой на форму/контакты (`contacts.html` или якорь формы заказа) и телефоном (брать номер как в шапке/футере, не выдумывать).
6. Подвал.

Иконки — собственные inline-SVG, без внешних иконочных шрифтов. Анимация появления по скроллу — можно использовать готовые классы из `main.js` (`.fade-in`, `.slide-in-*`, `.scale-in` + `.visible`), не писать дубль.

## 5. Фото и структура данных

Фото берутся **только из того, что уже есть в проекте** (качество пока низкое — позже заказчик заменит нейро-улучшенными). Источники:

1. **Слайдер «Наша продукция»** внизу главной, `src/index.html`, секция `products-showcase` (около строки 1336). Картинки лежат в `src/images/img/gallery/work/` (`work_books.jpg`, `work-journal*.jpg`, `work-etiketka*.jpg`, `work-box*.jpg`, `work-catalog.jpg` и др.); у слайдов уже есть готовые `data-title` и `data-desc` — можно взять за основу текстов.
2. **Блок «Что мы предлагаем?»** на главной и страницы услуг (`books.html`, `packagings.html`, `little-packagings.html`, `label.html`, `catalogs.html`, `journal.html`, `newspaper.html`, `coloring.html`, `photo-albums.html`, `textbook.html`, `calendars.html`, `posters.html`, `leaflets.html`, `booklets.html`, `badges.html` и др. — часть из них с фото продукции, часть без). Ещё картинки в `src/images/img/gallery/work/` (`work-calendar*.jpg`, `work-flaer.jpg`, `work-card.jpg`, `work-game.jpg`, `work-raskr.jpg`, `work-reklama2.jpg`, `work-textbook.jpg`, `work-mini-box2.jpg`).
3. **Статьи и новости** (`src/articles*.html`, `src/news*.html`, картинки в `src/images/img/articles/`, `src/images/img/news/`, `src/images/img/calendars/`): там, где на фото именно наша продукция (календари, книги, упаковка, открытки, кружки и т. п.). Искать поиском по `<img` в нужных файлах и просмотром самих файлов.

Правила отбора:
- Брать только фото нашей реальной продукции. Не брать стоковые картинки, ИИ-иллюстрации статей, фото оборудования, людей, мероприятий, логотипы, дипломы.
- Если фото слишком мелкое/размытое/с чужим логотипом — пропустить. Лучше 10–15 хороших карточек, чем 30 слабых.
- Фото с брендами и логотипами наших заказчиков **брать можно** — в портфолио выкладываем любые наши реальные работы (решение заказчика ТЗ). Пропускать только по качеству (мелкое, размытое, обрезанное), а не из-за бренда на продукции. Названия клиентов в подписях всё равно не придумывать и не писать, если их нет на самой странице-источнике.
- Отдельно: в письмах компаниям (email-рассылка, не часть этой задачи) фото из портфолио, где бренд конкурента адресата, показывать не будем — это решается при составлении писем, на страницу не влияет.
- Файлы **копировать** (не перемещать и не удалять оригиналы) в `src/images/img/portfolio/` с понятными именами: `kniga-01.jpg`, `zhurnal-01.jpg`, `upakovka-01.jpg`, … Позже заказчик заменит файл с тем же именем — и страница обновится.
- Не прописывать несуществующие пути (битые картинки недопустимы).

Данные карточек. Чтобы позже можно было легко добавлять работы, карточки в HTML должны быть **однотипными блоками**, а тексты — рядом с каждой карточкой (один `<li>`/`<article>` на работу, атрибут `data-category`). Добавление новой работы = копирование одного блока. Каждой карточке — осмысленный `alt` (например «Книга в твёрдом переплёте, тираж для издательства»).

Тексты «Подойдёт для» — предложение по категориям (можно уточнять по виду конкретной работы):
- Книги: издательства, авторы, выпускающие свои книги, организации к юбилею, школы и вузы.
- Журналы и газеты: корпоративные издания, органы власти, клубы и ассоциации, торговые сети.
- Каталоги и буклеты: АЗС, аптеки, кафе и рестораны, застройщики, медицинские центры, выставки и презентации.
- Упаковка и мини-коробки: производители продуктов и косметики, магазины подарков, интернет-магазины.
- Этикетки: производители продуктов, напитков, косметики, мелкие бренды.
- Календари: компании на новый год, банки, страховые, управляющие компании, школы.
- Раскраски и учебные издания: школы, детские сады, издательства, музеи.
- Реклама и листовки: магазины, салоны красоты, фитнес-клубы, рестораны, акции и раздача.

Тексты писать живым русским языком, без воды и штампов, без выдуманных цифр (тиражи, сроки и цены — не придумывать; если нужны — только то, что уже написано на сайте).

## 6. SEO и микроразметка

- `<title>`: «Портфолио типографии «Лазурь»: книги, журналы, упаковка, этикетки — примеры работ» (длина до ~70 символов; подогнать), `meta description` 150–160 символов, `rel="canonical"` → `https://lazurprint.ru/portfolio.html`.
- Open Graph и Twitter-теги (`og:type=website`, `og:url`, `og:title`, `og:description`, `og:image`, `og:site_name`, `og:locale`, `twitter:card`) — по образцу `src/news62.html`; `og:image` — одна из лучших картинок портфолио (абсолютный URL).
- Один `<h1>`; заголовки категорий и карточек — `<h2>/<h3>` с естественными ключевыми словами («Печать книг», «Печать каталогов и буклетов», «Изготовление упаковки»).
- JSON-LD: `CollectionPage` с `ImageObject`/`ItemList` по работам (по образцу JSON-LD в конце `src/news62.html`/`index.html`) или хотя бы `BreadcrumbList` + `CollectionPage`.
- Внутренняя перелинковка: ссылки на страницы услуг из карточек.
- Яндекс.Метрика и счётчики: скопировать блок `<head>` (скрипты метрики/gtag) со страницы-образца `src/news62.html` или `src/index.html`, как делают все страницы проекта.
- Страница автоматически попадёт в `sitemap.xml` при сборке (ничего делать не нужно).

## 7. Чего НЕ делать

- Не запускать `npm run dev`, `npm run build`, `npm run deploy` (пользователь держит свой dev-сервер; сборка с `clean` ломает `dist`). Проверку SCSS при необходимости — узким таском `npx gulp styles`.
- Не редактировать `dist/` и `build/`.
- Не коммитить и не пушить без явной просьбы пользователя.
- Не менять существующие скрипты/стили других страниц, кроме правок из п. 3.
- Не добавлять внешние зависимости (CDN-библиотеки) сверх уже используемых на сайте (Swiper).
- Не выдумывать данные (цены, тиражи, названия клиентов, отзывы).
- Фильтры по категориям (п. 4.2) — обязательны; заказчик может убрать их позже, поэтому сделать их изолированно: блок чипов и скрипт `portfolio.js` должны удаляться без поломки сетки.
- Если на странице нет реальных фото под какую-то категорию — не создавать пустую категорию и не ставить битых `<img>`.

## 8. Проверка результата

Dev-сервер пользователя пересоберёт `dist/` сам. Проверить в браузере у пользователя (или описать, что проверить ему):

1. В шапке: «О компании» → «Портфолио» открывает страницу (десктоп и мобильное меню).
2. В подвале есть ссылка «Портфолио».
3. На главной в первом экране вместо «Наши услуги» стоит «Портфолио», клик ведёт на `portfolio.html`.
4. На странице нет битых картинок, нет горизонтального скролла на 320 px, фильтры переключаются, lightbox открывается и закрывается (Esc/крестик/клик по фону).
5. В консоли нет ошибок.
6. Если правился `main.css`/`app.js` — ничего бампать не нужно: версия `?_v=` в HTML сама меняется по хешу исходников (см. `CLAUDE.md`, «Версия и кэш браузера»).
