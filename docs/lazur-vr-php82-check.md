# ТЗ: проверка сайта «Lazur VR» (lazur-wear.ru) после перехода с PHP 5.2 на 8.2 и переезда на новый сервер

Для сессии, в которой лежит проект lazur-wear.ru (Кодер), и затем для Тестера. Составлено 2026-10-14 (ночь) в сессии сайта lazurprint.ru, чтобы перенести файл в ту сессию.

## 1. Что произошло

- Хостинг NetAngels мигрирует контейнер `c112136` (на нём сайты `lazurprint.ru` и `lazur-wear.ru`) на другой сервер, в окружение с PHP 5.6–8.3. Бесплатно, автоматикой. **Меняются IP и имя хоста**, поэтому адрес SSH/SFTP нужно указать новый. DNS обновится сам.
- **PHP сайта lazur-wear.ru: было 5.2, станет 8.2.** Если автоматика переноса потребует, на время переноса стоит 5.6, после чего версию переключают на 8.2 (уточнить у Владимира, какой вариант получился; версию видно в панели NetAngels → сайт → вкладка PHP).
- Что за проект: конструктор футболок. Покупатель выбирает цвет и размер, наносит свой принт, кладёт в корзину, оформляет заказ, оплачивает; типография «Лазурь» наносит принт. Проект ещё в разработке, на хостинге уже есть и частично работает, критичным не считается.
- Владимир решил идти сразу на 8.2 (перескок через 5.3–8.1): ожидаются несовместимости старого кода, их нужно найти и исправить.

## 2. Часть А — для Кодера: аудит и правка кода

Сначала аудит локально (по исходникам проекта), потом проверка на сервере. Каждый найденный пункт — в список «нашёл / исправил».

### 2.1. Что искать в коде (типично ломается при 5.2 → 8.2)

Удалено или изменено, ломается сразу (фатальная ошибка или белый экран):
- функции `mysql_*` (удалены в PHP 7) → PDO или mysqli;
- `ereg`, `eregi`, `split`, `spliti`, `ereg_replace` → `preg_*`, `explode`;
- `each()`, `create_function()`, `get_magic_quotes_gpc()`, `magic_quotes`, `register_globals`, `$HTTP_POST_VARS` и подобные, `session_register`;
- `preg_replace` с модификатором `/e` → `preg_replace_callback`;
- конструктор класса методом с именем класса (`function ИмяКласса()`) → `__construct`;
- короткие теги `<?` без `php` и `<?=` (проверить, включено ли `short_open_tag`; безопаснее заменить на `<?php`);
- расширения `mcrypt`, `ereg`: нужны замены (`openssl`, `sodium`);
- фигурные скобки для символа строки `$s{0}` → `$s[0]`;
- `list()` с пустыми элементами и присваивание `$this`; `break`/`continue` с переменной; `array_key_exists` на объекте.

Строже в PHP 8 (TypeError, Warning, Deprecated; проверять журнал ошибок):
- арифметика и сравнение со строкой, не являющейся числом, `count()` и функции массивов на `null` и не-массиве;
- передача `null` в строковые функции (`strlen(null)`, `trim(null)`: Deprecated с 8.1, проверить);
- `0 == "строка"` ведёт себя по-другому (в PHP 8 `0 == "abc"` теперь false) — условия в проверках;
- обращение к несуществующему ключу массива и переменной (Warning), к свойству `null`;
- функции с обязательными параметрами после необязательных;
- `strftime` и `date_sunrise` (Deprecated в 8.1), `utf8_encode`/`utf8_decode` (в 8.2 Deprecated), динамические свойства объектов (Deprecated в 8.2: объявлять свойства в классе);
- `$GLOBALS` теперь только для чтения целиком, `static` в замыканиях, `FILTER_SANITIZE_STRING` (Deprecated 8.1).

Что ещё зависит от окружения:
- расширения: `gd` (превью и наложение принта), `mbstring`, `json`, `curl`, `zip`, `fileinfo`, `session`, `pdo_mysql` или `mysqli`. Проверить `phpinfo()` или `php -m` на сервере;
- настройки: `upload_max_filesize`, `post_max_size`, `memory_limit` (большие картинки принтов), `max_execution_time`, `date.timezone`;
- хост MySQL в конфиге проекта (уточнить у поддержки: после переезда может остаться `localhost`, может измениться);
- абсолютные пути в коде и конфиге (если зашит путь вида `/home/c112136/...`, проверить, остался ли он);
- cron-задачи, если есть (сохранились ли после переезда);
- права на папки загрузки (принты, превью, временные файлы).

### 2.2. Интеграции — внимание отдельно

- **Оплата** (платёжная система, callback/webhook, подпись запросов): адрес для уведомлений и IP-фильтры, TLS и версия curl, новый IP сервера (если платёжка фильтрует по IP — сообщить Владимиру, нужно обновить в её кабинете).
- **Почта** (`mail()` или SMTP): отправка писем покупателю и сотрудникам, заголовки, кодировка, ящик отправителя.
- **Загрузка и обработка принта**: типы файлов, размер, GD (`imagecreatefrom*`, `imagejpeg`), нехватка памяти на больших картинках.
- **Сессии и корзина**: куки, `session_start`, сохранение корзины между страницами.
- **Внешние API и скрипты** (если есть): ключи, URL, `curl`.

### 2.3. Как работать

1. Скопировать проект в локальную папку (если ещё нет) и прогнать `php -l` (8.2) по всем `.php`. Локально у Владимира PHP 8.3 (Laragon), этого достаточно для проверки синтаксиса.
2. Просмотреть код по списку 2.1, составить список проблем.
3. Исправить совместимо с 8.2 (по возможности без нового синтаксиса там, где это не нужно).
4. После выкладки смотреть журнал ошибок PHP на сервере (`error_log` рядом со скриптами или в панели хостинга) при каждом проходе Тестера.
5. Выкладку (коммит, пуш, заливка) делать только по слову Владимира. Секреты в файлы проекта не писать.

## 3. Часть Б — задание Тестеру (qa-задание)

Тестер проект не правит, только проверяет и пишет отчёт. Ничего не оплачивать реальными деньгами, реальных заказов не оформлять без явного «да» Владимира в чате. Если оплату можно проверить в тестовом режиме платёжной системы, использовать только его. Пароли и коды вводит только Владимир.

### 3.1. Что проверять (сайт lazur-wear.ru)

Для каждого шага: работает / не работает / работает частично, скриншот, текст ошибки, консоль браузера (вкладка Console и Network).

1. Главная и все внутренние страницы открываются без белого экрана, 500 и 404; ссылки, картинки, стили и скрипты загружаются (в Network нет красных запросов).
2. Конструктор: выбор модели, цвета, размера; предпросмотр обновляется.
3. Загрузка своего принта: JPG, PNG, разные размеры (маленькая и большая картинка, 5–10 МБ), неподходящий файл (должна быть понятная ошибка, а не белый экран); принт появляется на футболке, его можно двигать и менять размер.
4. Сохранение макета (если есть), повторное открытие.
5. Корзина: добавление, изменение количества, удаление, сумма и цена, сохранение при переходе между страницами и после перезагрузки.
6. Оформление заказа: форма (имя, телефон, e-mail, адрес), проверка полей, сообщения об ошибках.
7. Оплата: до страницы платёжной системы и возврат на сайт (успех и отмена). Реальную оплату не проводить; если есть тестовый режим, пройти в нём.
8. Письма: пришло ли письмо покупателю и сотрудникам после заказа (если для проверки нужен ящик, сообщить Владимиру, не использовать чужие почты).
9. Админская часть (если есть): вход, список заказов, просмотр макета и принта, смена статуса.
10. Мобильная ширина (375 px) и обычная (1280 px).
11. Общее: текст ошибок вида «Warning», «Notice», «Deprecated», «Fatal error» или «Parse error» на страницах (видно в тексте страницы и в исходнике).

### 3.2. Формат отчёта

Таблица: № шага, что делали, результат, ошибка/скриншот. Отдельно список всех замеченных ошибок PHP и JS, отсортированный по важности (блокирует заказ / портит вид / косметика). В конце вывод: можно ли принимать заказы или что нужно исправить. Отчёт передаётся Кодеру, который исправляет код (часть А) и просит повторную проверку.

## 4. Чек-лист после переезда для lazurprint.ru (на всякий случай)

Если Кодер сайта lazurprint.ru не успел, то же самое проверяет Тестер:
- главная и случайные страницы, форма заявки (отправка и приход письма менеджеру);
- вход в админку `lazurprint.ru/admin`, карточка товара, загрузка фото;
- для Кодера: новый адрес SSH/SFTP в `.env`, `npm run deploy` проходит, `node admin-remote-exec.js …` работает, адрес MySQL в конфиге админки.

## 5. Критерии приёмки

- На всех страницах и во всех шагах из 3.1 нет фатальных ошибок и сообщений PHP (Warning, Deprecated).
- Сценарий «выбрал футболку, загрузил принт, положил в корзину, оформил заказ» проходит до оплаты, оплата проходит в тестовом режиме.
- Письма уходят.
- Журнал ошибок PHP после прохода пуст или содержит только согласованные Владимиром замечания.
