# CLAUDE.md

## Команды

```bash
npm run dev      # clean → сборка → browser-sync (baseDir: dist) + watch
npm run build    # продакшен: минификация HTML/CSS/JS, sitemap.xml
npm run deploy   # build + заливка build/ на хостинг (deploy.js, см. docs/claude/deploy.md)
```

Узкие таски: `npx gulp styles`, `npx gulp scripts`, `npx gulp htmlMinify`, `npx gulp sitemap`.

Свои инструменты (сборку и dev-сервер не трогают):

```bash
npm run check                          # битые ссылки/картинки/скрипты, регистр имён, canonical — по src/, без сборки
node tools/check-links.js page.html    # то же для отдельных страниц
node tools/js-inventory.js [page.html] # какие скрипты где подключены, дубли, страницы без app.js, неиспользуемые файлы
npm run js-smoke -- --all | page.html  # JS страниц в jsdom: ошибки, кнопки формы, слайдеры, видео, отзывы (нужен jsdom — шапка tools/js-smoke.js)
node tools/js-form-test.js             # сценарии формы заявки: капча, ошибки отправки, закрытие (после npx gulp scripts)
npm run new-page -- article|news "Заголовок" --prefix xyz [--desc "..."]   # заготовка нового материала
```

**После правок HTML — прогонять `node tools/check-links.js <изменённые страницы>`**: это проверка вместо запуска сборки. Предупреждения (`[предупр.]`) на код выхода не влияют; известные — три видео `printing-museum.html` (в git их нет, на хостинг залиты вручную). Ссылка-кнопка, которую открывает JS (форма заявки и т.п.), помечается `role="button"` — тогда проверка не считает её битым якорем. Canonical — только в `<head>` (в 2026-10 перенесён туда со 122 страниц).

> **НЕ запускать `npm run dev` / `npm run build` «на проверку».** У пользователя обычно уже поднят свой dev-сервер с watch — он сам пересобирает `dist/` при правке `src/`. `dev`/`build` начинаются с `clean` (`del(['dist','build'])`): запущенные параллельно с dev пользователя, они стирают `dist` на ходу, и картинки (2400+ файлов и тяжёлые видео) не успевают докопироваться — страница остаётся с битым логотипом/иконками (так уже ломалось). Проверить компиляцию — узким таском (`npx gulp styles`; он тоже пишет в `dist`/`build`). Свои статические серверы для предпросмотра не поднимать. Временный сервер для теста (например, `php -S`) — сначала проверить, не занят ли порт сервером пользователя; при уборке убивать только PID, который запустил сам, а не «что висит на порту».

`dev` и `build` пишут результат **одновременно в `dist/` и `build/`**. Разница — флаг `prod` (таск `isProd`): sourcemaps только в dev; минификация (`cleanCSS`, `uglify`, `htmlMin`) и `sitemap.xml` — только в build.

## Архитектура сборки (gulpfile.js)

**Два независимых конвейера JavaScript — не перепутать:**

1. **Бандл `app.js`** (таск `scripts`): `src/js/components/**/*.js` + `src/js/main.js` → Babel → concat. `main.js` — общая логика всех страниц: бургер, выпадающие меню хедера, анимации появления (`.fade-in`/`.slide-in-*`/`.scale-in` + `.visible`), антиспам-поля формы.
2. **`src/resources/`** (таск `resources`): копируется **как есть** в корень `dist`/`build`. Постраничные скрипты (`index.js`, `catalog.js`, `events.js`, `about.js`, …) подключаются вручную `<script>` на нужных страницах; там же сторонние либы (swiper, choices, just-validate, inputmask, lazyload, rellax, simplebar), PHP формы и `robots.txt`.

Новый общий JS → `src/js/`. Скрипт конкретной страницы или внешняя либа → `src/resources/` + тег `<script>`.

**Подключение JS на странице** (наведено в 2026-10, проверяется `npm run js-smoke`):
- Всё в `<head>`, всё `defer`, пути относительные (`app.js`, не `/app.js`), в таком порядке: `inputmask.min.js` → `just-validate.min.js` → [`swiper-bundle.min.js`] → [общие: `swiper-JS.js`, `about.js`, `work.js`, `map.js`] → [скрипт страницы] → `app.js`. Внешние счётчики — `async`. Синхронных `<script src>` и Swiper с CDN не ставить.
- `inputmask` + `just-validate` нужны **на каждой странице с подвалом** (там форма заявки), иначе форма уходит без проверки.
- Swiper — одна версия, локальные `swiper-bundle.min.js/.css` (11.2.10); подключать только при наличии слайдера. Общий скрипт — только если на странице есть его блоки: `swiper-JS.js` — `.steps__swiper`/`.benefit__right-cnt`, `about.js` — видео `.play-1`, `work.js` — отзывы `.reviews__list`.
- Каждый скрипт страницы — в IIFE или `DOMContentLoaded`, `querySelector` — с проверкой на `null` (у всех классических `<script>` одна глобальная область: повтор `const` в двух файлах ломает второй целиком). Инлайн с `new Swiper` — внутри `DOMContentLoaded` (Swiper грузится `defer`).
- Модалки: закрытие крестиком, фоном и Esc; видео при закрытии — `pause()` + `removeAttribute('src')` + `load()` (`src = ''` грузит адрес страницы). Swiper: в брейкпоинте менять только то, что задано и в соседних (параметр, не указанный в брейкпоинте, не возвращается к базовому при обратном ресайзе); один экземпляр на элемент. Тяжёлые библиотеки «по кнопке» (pdfmake в `catalog-pdf.js`) — грузить при первом нажатии, не тегом в `<head>`.
- Привести страницу к шаблону: `node tools/js-normalize.js --dry page.html` (затем без `--dry`; `--wrap-inline` — обернуть инлайны со Swiper).

- **CSS:** все партиалы импортируются в `src/styles/styles.scss` → `main.css`. Новый `_*.scss` без `@import` в `styles.scss` в сборку не попадёт. Стили отдельных статей/страниц — в `src/styles/articles/` (`@import 'articles/имя';`).
- **HTML:** страницы — `src/*.html`, общие блоки (header, footer, consultation, reviews, steps…) — `src/html/*.html`, вставка через gulp-file-include: `@@include('html/header.html', {})`. Шапку/подвал менять в `src/html/`, не в страницах. Счётчики (Яндекс.Метрика + Google Analytics) — `src/html/counters.html`, первой строкой `<head>` каждой страницы; копии кода счётчиков в страницы не вставлять.
- **sitemap.xml** генерирует таск `sitemap` (последний шаг build) из `src/*.html`, `lastmod` — дата последнего git-коммита файла. Новая страница попадает туда сама. Служебные исключены regex'ом `exclude` в `sitemapTask` (`google*`, `yandex_*`, `thanks`, `forms`) — новую служебную страницу добавить туда.
- **Шрифты:** `.ttf` из `src/fonts/` → `.woff`/`.woff2`. **Изображения:** png/jpg/svg — таск `images`; webp/mp4/mov/ico/pdf — `imagesCopy`; `src/images/svg/` → `sprite.svg`.

### Версия и кэш браузера

`gulp-version-number` (таск `htmlMinify`) дописывает `?_v=…` к css/js в HTML (и пишет `src/version.json`). Значение — `assetsVersion()` в gulpfile: `версия из package.json` + 8 символов sha256 исходников `src/styles`, `src/js`, `src/resources` (только .scss/.css/.js), например `1.0.17.e6834187`. **Любая правка стилей/скриптов сама меняет версию — вручную бампать ради сброса кэша не нужно.** Пока исходники не менялись, значение стабильно между сборками — инкрементальный деплой не перезаливает HTML зря. `version` в `package.json` бампать по желанию, как номер релиза в коммитах.

## Форма заявки (mail.php)

Секреты (пароль SMTP-ящика noreply, ключ reCAPTCHA) в коде не хранятся: `mail.php` читает их из `mail-config.php` на хостинге уровнем выше `www` (`/home/c112136/lazurprint.ru/mail-config.php`). Локальная копия — `mail-config.php` в корне (в `.gitignore`), в git — шаблон `mail-config.example.php`. Деплой конфиг НЕ заливает. **Кнопка, открывающая форму, — атрибут `data-open-form`** (необязательно `data-form-title` / `data-form-desc` / `data-form-text`), своих обработчиков открытия не писать; логика и ленивая загрузка reCAPTCHA — `src/js/components/form-modal.js` в `app.js`, `recaptcha/api.js` на страницы не подключать. **`mail.php` при успехе не выводит ничего** — клиент (`main.js`) считает успехом только пустой ответ, любой текст (в т.ч. `echo`/предупреждение PHP) — ошибкой; известные ответы-ошибки перечислены в шапке `mail.php`, новый — добавить и туда, и в `main.js`. Обязательны имя (до 50 символов) и телефон, email — по желанию. В правилах just-validate свои `rules` поля заменяют встроенные целиком (для email нужно явно `email: true`). Антиспам: honeypot + минимальное время заполнения (поля добавляет `main.js`; `$requireTimestamp = true`) + не больше 5 **ушедших** заявок/час с IP (неудачные попытки лимит не тратят; при лимите — ответ «Слишком много заявок», посетитель видит пояснение). Проверить логику `mail.php` локально без почты и Google — заглушками, как в сессии аудита (PHP без curl: свои `curl_*` и класс `PHPMailer` в обёртке перед `include`).

Архив фото на `events.html` — ссылка зашифрована паролем (`ARCHIVE` в `events.js`), сменить пароль/ссылку: `node tools/archive-link.js "Пароль" "ссылка"`.

## Админ-панель (admin/)

Отдельное PHP+MySQL приложение для сотрудников (учёт новых сувениров), **не часть gulp-сборки**. Хостинг — **PHP 7.3**: без синтаксиса PHP 8 (`match`, `??=`, стрелочные функции, типизированные свойства), хотя локально PHP новее. Локально — Laragon + `admin/serve.ps1` (порт 8000).

**С 2026-09-15 панель работает на `lazurprint.ru/admin` со своей прод-базой MySQL** (там работают Ксюша и Надя; локальная `lazur_admin` — тестовая). Поэтому `admin/tools/link-site-image.php` / `mark-site-updated.php` запускать на хостинге: `node admin-remote-exec.js admin/tools/<script>.php <аргументы>` (SSH по `DEPLOY_SFTP_*` из `.env`). Локальный `php` отработает без ошибок, но против пустой локальной базы. **Только после реального деплоя** правки на сайт — иначе в панели карточка станет «опубликованной» раньше, чем появится на сайте.

## Важное

- `dist/` и `build/` — артефакты сборки (в `.gitignore`), не редактировать. Правки — только в `src/`.
- Коммит, пуш и `npm run deploy` — только по явной просьбе пользователя и после того, как он посмотрел результат. **«Деплой» от пользователя = всё сразу: коммит → пуш → `npm run deploy`** (подтверждено 2026-10-08, отдельно просить коммит/пуш не нужно). В коммит — только файлы задачи; чужие незакоммиченные правки и инбокс `src/images/Новая продукция/` не трогать.
- WebFetch/WebSearch — отложенные инструменты: подгрузить через `ToolSearch` (`select:WebFetch`), не говорить «нет доступа к ссылкам». Если нужен полный текст статьи — `curl -sL -A "Mozilla/5.0" URL` в scratchpad. Сайты на Tilda (printinsider.ru) отдают 403 на «голый» URL — помогает ссылка с `?utm_...`.

## Журнал дня и отчёт для Татьяны Александровны

**1. После каждой завершённой задачи** (любой, как бы её ни поставили) — один пункт в [`DAILY-LOG.md`](DAILY-LOG.md) под заголовком `## YYYY-MM-DD` (создать, если задача первая за день). Сразу языком бизнеса («поправили оформление карточки товара», а не «поправил SCSS»). Промежуточные шаги не логировать. В начале нового месяца прошлый месяц переносить в `docs/logs/daily-log-YYYY-MM.md`.

**2. Отчёт — только по команде** («напиши отчёт» и похожее). **Сначала перечитать в `DAILY-LOG.md` записи за нужную дату целиком** и брать пункты оттуда, а не из памяти сессии (2026-10-08 так пропустили «Как заказать»). Татьяна Александровна не разбирается в программировании:

- без технических терминов и названий файлов — только суть для бизнеса/сайта;
- коротко: 1–3 предложения на день (списком, если пунктов много);
- **от первого лица пользователя в единственном числе** («сделал», «начинаю»), без «мы» и без упоминания нейросети/ассистента;
- начинать с «Татьяна Александровна, добрый день!», без слов «отчёт за сегодня»;
- выдавать **в блоке кода** обычным текстом, номера пунктов набирать вручную («1)») — иначе при копировании форматирование теряется.

## Самостоятельный выбор задачи

Если пользователь просит самому придумать, над чем поработать («предложи что-нибудь», «выбери сам, что улучшить»):

1. Посмотреть «Идеи на будущее» в [`WORKLOG.md`](WORKLOG.md) — если там есть актуальное, предложить его первым.
2. Иначе придумать **одну** задачу среднего размера, описать в 2–3 предложениях и дождаться подтверждения.
3. После выполнения — запись в «Выполнено» в `WORKLOG.md` (и отметить идею в бэклоге). В «Выполнено» — **только** задачи из этого сценария, не обычные поручения.
4. Идеи, возникшие по ходу любой работы, но не сделанные сейчас, — в бэклог `WORKLOG.md`.
