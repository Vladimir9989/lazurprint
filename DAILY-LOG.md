# DAILY-LOG.md

Журнал дня — что сделано по проекту, по датам. Пополняется после каждой завершённой задачи
(любой, не только самостоятельно выбранной — для тех есть отдельный `WORKLOG.md`), сразу
простым языком бизнеса. Служит источником для отчёта Татьяне Александровне: по команде
«напиши отчёт» ассистент читает записи за нужный день отсюда и составляет короткое
сообщение для пересылки. Подробности правила — в `CLAUDE.md`, раздел «Журнал дня и резюме
для Татьяны Александровны».

## 2026-09-13

- Начали делать внутреннюю панель учёта новой сувенирной продукции (для фотографа,
  бухгалтерии, кладовщика и руководства) — по ТЗ, которое обсуждали раньше. Сделан первый
  рабочий кусок: сотрудники смогут сами регистрироваться (по кодовому слову) и входить
  надолго без повторного ввода пароля, заводить карточку нового товара, добавлять к ней фото
  прямо с телефона, а система сама подскажет, чего не хватает — фото или цены. Пока это
  видно только локально на компьютере разработчика, на сайт ещё не выкладывали — следующим
  шагом сделаем связь с реальным каталогом на сайте и публикацию.
- Доработали панель учёта продукции по итогам тестирования: после сохранения карточка
  теперь сразу показывается как готовая запись, а не остаётся открытой формой; цена товара
  стала видна прямо в общем списке карточек, а не только внутри самой карточки; заметки и
  комментарии к карточке теперь подсвечиваются меткой «новый» для каждого сотрудника отдельно,
  пока он сам не отметит, что прочитал — так не придётся открывать все карточки подряд, чтобы
  проверить, не оставил ли кто-то вопрос или уточнение. Добавили кнопку закрытия карточки
  товара, чтобы быстро вернуться к общему списку.
- Панель учёта продукции научилась сверяться с настоящим каталогом на сайте: вкладка
  «Что на сайте» теперь по кнопке разбирает реальный каталог сувениров (589+ позиций) и
  показывает его списком с поиском и фильтром по категории. Разработчик может привязать
  карточку товара к конкретной позиции на сайте, выбрав её из этого списка (не вписывая
  вручную), а после привязки система сама отмечает товар «опубликован», как только видит
  его в свежем разборе каталога — вручную ставить эту галочку больше не обязательно.
- Настроили сквозной процесс публикации новой продукции: разработчик одной кнопкой в
  админке скачивает архив с фото и данными всех карточек, готовых к публикации, отдаёт его
  Ассистенту — тот сам обрабатывает фото и добавляет товары на сайт, а после этого достаточно
  один раз нажать «Обновить список» в админке, и все опубликованные карточки сами
  отмечаются готовыми, без ручной галочки по каждой. Проверили процесс на реальной тестовой
  карточке — сработало.
- Доработали вкладку «Что на сайте»: теперь напротив каждого товара сразу видна маленькая
  фотография (крупнее — при наведении курсором), а не просто путь к файлу текстом. Добавили
  кнопку «Редактировать» у любой позиции — Надя сможет сама поправить название, артикул или
  цену прямо из этого списка, если они изменились у уже выложенного на сайт товара. Такая
  карточка получает пометку «изменено, нужно обновить на сайте», которая держится, пока
  разработчик не подтвердит, что перенёс изменения на сайт.
- Такие правки уже опубликованных товаров теперь тоже можно выгружать одной кнопкой:
  на главной появилась «Экспорт изменений» — скачивается файл только с новыми данными
  (название/артикул/цена), без фото, ведь товар и так уже на сайте. Разработчик отдаёт файл
  Ассистенту, тот меняет данные в нужной карточке каталога на сайте, и пометка «нужно
  обновить» с товара автоматически снимается.
- На опубликованной карточке товара появилась кнопка «Удалить оригиналы» (для разработчика):
  убирает с диска тяжёлые исходные фото, когда они уже не нужны — сама карточка, уменьшенная
  фотография и вся история остаются на месте. На главной странице теперь виден счётчик,
  сколько места на диске занимают ещё не удалённые оригиналы.
- Панель учёта продукции научилась сама писать письма на почту: фотографу — когда завели
  карточку без снимка, бухгалтеру — когда без цены/артикула, разработчику — когда карточка
  готова к публикации, автору карточки — когда товар опубликован на сайте, а также письма о
  новых заявках на регистрацию и об их подтверждении. На компьютере разработчика отправка
  писем сейчас отключена нарочно (чтобы тестирование не беспокоило сотрудников настоящими
  письмами) — включится, когда панель переедет на боевой сервер.
- Добавили ещё одно письмо разработчику: если Надя поправит название/артикул/цену уже
  выложенного на сайт товара (например, через кнопку «Редактировать» в разделе «Что на
  сайте»), теперь сразу приходит письмо, что это правка существующей позиции, а не новый
  товар — фото менять не нужно, только данные в карточке на сайте.
- Настроили три автоматические задачи по расписанию (запускаются сами, без участия
  сотрудников): ночью панель сама сверяется с настоящим каталогом на сайте (то же самое,
  что раньше делали кнопкой «Обновить список»); раз в неделю всем сотрудникам (кроме
  наблюдателя) приходит письмо-сводка, если по каким-то карточкам давно нет движения;
  и раз в неделю с диска сами удаляются тяжёлые исходники фото у товаров, опубликованных
  больше 45 дней назад — за неделю до этого разработчику приходит письмо-предупреждение
  со списком, что именно скоро почистится.
- Доделали раздел «Пользователи» в панели учёта продукции: администратор теперь может прямо
  из списка сотрудников поменять роль или заблокировать/разблокировать доступ — без правки
  базы вручную. Блокировка срабатывает сразу, даже если сотрудник в этот момент работает в
  панели. Систему нельзя случайно оставить без единого администратора — она не даст
  заблокировать или понизить в роли последнего. Также заработало самостоятельное
  восстановление пароля: сотрудник, который его забыл, теперь получает письмо со ссылкой и
  сам задаёт новый пароль, без обращения к разработчику; администратор при необходимости
  тоже может выслать такую ссылку сотруднику одной кнопкой. Это был последний открытый пункт
  по техническому заданию — панель по функциональности готова полностью, дальше только
  перенос на боевой сервер.
